# Хранилище ИИ-агентов

## Цель и границы
Отдельный раздел «ИИ-агенты» показывает локальные временные данные и рабочие папки,
их размер на диске, принадлежность агенту, признаки проекта и рекомендации.
Swift 6, macOS 14; без зависимостей, полного обхода диска и сетевой отправки данных.

## Источники
Codex: ~/.codex/worktrees, ~/.codex/tmp. Cursor: ~/.cursor/worktrees.
Claude: ~/.claude/worktrees, ~/.claude/debug, ~/.claude/projects (история, только просмотр).
Известные кэши Claude/Cursor из KnownCacheScanner. В разрешённых projectRoots ищем
только .claude/worktrees, .cursor/worktrees и .codex/worktrees, с ограничением глубины
и пропуском зависимостей. Пользователь может добавить отдельный каталог рабочих
данных агента; неизвестное происхождение никогда не даёт права на очистку.

## Проверки
Физический объём без перехода по symlink, дата самого свежего вложенного объекта,
полнота обхода, .git (каталог или gitdir-файл), вложенные репозитории, bare Git,
манифесты проектов и исходники. Это локальная структурная Git-проверка: она не
доказывает наличие remote, push или чистоту индекса. Любой Git защищён, включая
сломанный gitdir. История сессий, неизвестные рабочие данные и проекты защищены.
Ошибки чтения, ссылки, превышение лимита обхода означают только просмотр.

Кандидаты очистки: известные кэши и диагностические логи, временные .tmp/.log/.cache
файлы в известном tmp-каталоге; не менялись минимум 7 дней, обход полный, без
Git/проектов/ссылок. Каталог tmp с неизвестным содержимым только для просмотра.
Перед удалением повторить классификацию и проверить закрытие владельца, identity,
SafetyRules. Корзина только через ScanEngine. Никакого удаления Git worktree,
prune или автоматического перемещения: это сломало бы связь с агентом/репозиторием.

## UI и поток данных
AgentStorageScanner (Scanner, Sendable) → AgentStorageReport →
AgentStorageViewModel (@Observable @MainActor) → AgentStorageView.
Отдельная вкладка рядом с Docker; сводка размера/очищаемого объёма, полосы по агентам,
сортировка папок по размеру, поиск/фильтр, статусы, причины, Finder, добавление папки,
отмена сканирования, ошибки/частичное покрытие. Ничего не выбрано по умолчанию.
Предпросмотр фиксирует пути/размеры, удаление лицензируется как существующая очистка.
Рекомендации переноса объясняют ручной архив/проверку Git и не обещают безопасный mv.

## Проверка
Fixture-тесты: известные источники, вложенный Git, gitdir-файл, bare repo, проект без
Git, свежий вложенный файл при старом родителе, symlink, неполный обход, пересечение
корней, новый Git после предпросмотра, запрет удаления рабочих папок, лицензия,
повторный scan/cleanup, отмена. Полный XCTest и Debug build, визуальная проверка UI.

## Исследование и следующие возможности
- [Claude worktrees](https://code.claude.com/docs/en/worktrees): сохраняет работу при
  изменениях и непроверяемом состоянии; worktrees по умолчанию внутри проекта.
- [Codex worktrees](https://developers.openai.com/codex/app/worktrees/): управляет
  количеством checkout, каждый может содержать собственные зависимости и сборки.
- [Cursor worktrees](https://cursor.com/docs/configuration/worktrees): ограничение
  количества и периодическая очистка. Следует проверять фактические папки на диске.
- [Git worktree](https://git-scm.com/docs/git-worktree): рабочие папки связаны общей
  metadata; для переноса и удаления нужны штатные операции Git.

Приоритеты расширения: история роста и лимиты по агентам; закрепление проектов;
уведомления о старых крупных папках; поиск повторяющихся node_modules/сборок;
интеграция с реестрами активных сессий; проверка незапушенных коммитов и worktree
locks; экспорт отчёта; архив с проверкой восстановления; поддержка других агентов
через проверяемые адаптеры. Автоочистку включать только после надёжной проверки
активных сессий и возможности восстановления.
